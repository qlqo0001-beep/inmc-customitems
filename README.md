# inmc-customitems

아이템을 직접 만들어 **다른 INMC 플러그인 전부**에서 쓰게 하는 플러그인. MMOItems 가 하는 일을
이 워크스페이스 안에서 한다.

모든 설정이 GUI 로 된다. `items.yml` 은 열어볼 수 있지만 열 필요가 없다.

---

## 필요한 것

| | |
|---|---|
| 서버 | Paper 1.21+ |
| 필수 | **`inmc-core`** — Kotlin 런타임과 공용 프레임워크를 들고 있습니다 |
| 선택 | 없음 — 다른 플러그인은 core 를 통해 이 플러그인의 아이템을 가져갑니다 |
| 서버 설정 | 블록 상태 방식 **커스텀 블록**을 쓸 때만 Paper 의 갱신 끄기 두 줄 — [커스텀 블록](#커스텀-블록) 참조 |

ItemsAdder·Nexo·Oraxen 와 **같이 쓸 수 있습니다.** 서로 다른 네임스페이스라 충돌하지 않고,
core 가 둘 다 알아봅니다.

`/커스텀아이템` · 별칭 `/customitems` `/ci` `/아이템` · 권한 `incustomitems.admin`

|---|---|
| `/커스텀아이템` 또는 `관리` | 관리 화면 |

| `/커스텀아이템 제작` | 제작대 목록(관리) |
| `/커스텀아이템 리팩` · `리팩 빌드` · `리팩 정보` | 리소스팩 |

`/장비` (별칭 `/장신구` `/equipment` `/acc`) · 권한 `incustomitems.equipment`(기본 모두) — 장착 칸(장신구·부적·유물).

## 아이템 만들기

1. 바탕이 될 아이템을 **손에 들고** `/커스텀아이템 관리`
2. 첫 장은 **종류 서랍**입니다(무기·방어구·도구·소모품·장신구·재료·보석·기타, 가운데 전체 보기). 만들 종류의 서랍에
   들어가 `손에 든 것으로 새 아이템 만들기` 를 누르고 이름을 적는다(첫 장에서 누르면 종류를 재질로 짐작합니다)
3. 설정 화면이 열린다 — 여기서 전부 고친다

툴팁은 **이름 → 종류(`⚔ 무기`) → 인첸트 → 능력치 → 강화·공격 방식·소켓·보석·소모품·기능·요구 조건·세트·인첸트 상태 → 등급 배지(`▬▬ ✦ 전설 ✦ ▬▬`) → 설명** 순입니다.
이름을 적으면 등급 색이 앞에 붙습니다.

- 바닐라가 로어 위에 그리던 **인챈트**와 아래에 그리던 **"주로 사용하는 손에 있을 때"**(기본 공격력·속도·방어)는 숨기고, 그 내용을
  인첸트·능력치 자리에 옮겨 적습니다. 공격력·공격 속도는 바닐라처럼 맨손 기준값을 더한 값(곡괭이 "6 공격력 · 1.2 공격 속도")입니다.
  아이템 설정의 숨김 옵션에서 인챈트·속성을 숨기면 옮겨 적지도 않습니다
- 강화·보석·수식어로 늘어난 몫은 능력치 옆에 **`(+n)`**, 원래 없던 능력치면 **초록 줄**로 덧붙습니다
- 커스텀 인첸트 줄(인첸트 플러그인)도 인첸트 자리에 들어갑니다. **"인첸트 칸 n/m" 은 아이템에 적지 않고** 관리 화면의 미리보기에서만 보입니다
- 모루·부여대·명령어로 인챈트를 바꿔도 다음 자동 갱신(손에 쥘 때·주울 때·접속·상자 열 때)에 로어가 따라옵니다
아이템 이름(id)은 한글도 됩니다.

목록에서는 **좌클릭 설정 · Shift+좌클릭 한 개 받기 · 우클릭 삭제**입니다.

### 대분류와 소분류

종류(대분류) 하나에 아이템이 많아지면 **소분류**로 나눠 봅니다 — MMOItems 에서 부모 타입을 둔 타입(`일반무기` → SWORD,
`강화석` → CONSUMABLE)과 같은 것입니다. 종류처럼 **표시와 걸러보기 전용**이라 동작은 바꾸지 않습니다.

- 소분류가 있는 종류를 누르면 **소분류 서랍**이 열립니다(없으면 지금처럼 곧바로 목록). 아래에 **○○ 전부** ·
  **분류 없음**(소분류를 안 정한 것) · **새 소분류** 버튼.
- 서랍 좌클릭 보기 · 우클릭 이름 바꾸기 · Shift+좌클릭 손에 든 것으로 아이콘(모델 번호·커스텀아이템 모양 그대로) · Shift+우클릭 지우기(아이템은 지워지지 않고
  분류 없음으로). 소분류가 하나도 없는 종류는 목록 화면의 **소분류** 버튼에서 만듭니다.
- 아이템의 종류는 설정 화면의 **종류** 칸을 눌러 **고르기 화면**에서 고릅니다 — 종류마다 아이콘(커스텀 모델 그대로)·기준 종류·그 종류의
  아이템 수가 보입니다(2026-09-30 전에는 좌/우클릭으로 돌렸다).
- 아이템 쪽은 설정 화면의 **소분류** 칸에서 고릅니다. 종류를 바꾸면 소분류는 떨어집니다(소분류는 종류에 딸려 있다).
  소분류 서랍 안에서 손에 든 것으로 만들면 그 소분류로 들어갑니다.
- 저장은 `categories.yml`(순서 = 서랍 순서), 아이템의 `category`. 기본값은 옮겨 온 MMOItems 아이템을 나눠 둔 25개 —
  무기 일반~신화 · 방어구 세트 넷 · 도구 곡괭이/낚싯대 · 소모품 강화석/유물 강화권/도구 교환권/랜덤 상자/기타 · 재료 둘 · 마석 일곱.

### 종류 만들기 · 이름 바꾸기

`관리 → 종류 관리`(첫 화면 4번). 기본 10종은 **이름·아이콘·기호**를 바꿀 수 있고, **새 종류**(보호권·열쇠·캡슐 …)를 만들 수 있습니다.
새 종류는 **동작 기준**으로 기본 종류 하나를 고르고 그것처럼 동작합니다 — "보호권"을 소모품 기준으로 만들면 소모품처럼 쓰이고,
"수호석"을 부적 기준으로 만들면 가방·장착 칸에서 효과가 납니다. 이름·기호는 서랍과 로어 첫 줄에 보입니다.

- 만든 종류는 첫 화면 맨 아래 줄(아홉까지)에 서랍으로 보이고, 소분류도 따로 가질 수 있습니다
- 아이템 설정의 **종류** 칸을 누르면 나오는 고르기 화면에 기본 종류와 만든 종류가 함께 나옵니다
- 지우면 아이템은 동작 기준 종류로 돌아가고 그 종류의 소분류는 사라집니다
- 저장은 `types.yml`, 아이템은 `type`(동작)과 `custom-type`(만든 종류 id)

설정 화면(허브)은 **탭 넷**으로 나뉩니다(2026-09-30). 미리보기 아래의 탭을 누르면 그 묶음만 넓게 보이고, 세부 화면에서
돌아오면 **보던 탭**으로 옵니다. 탭 아이콘에 그 탭에서 **바꾼 것**이 요약돼 있어 열기 전에 어디를 볼지 압니다. 그 아이템에
뜻이 없는 칸(부적이 아닌데 "중복 안 함", 도구가 아닌데 "채굴 등급", 장신구·부적·유물이 아닌데 "배낭"·"효과가 나는 곳")은 보이지 않습니다.

| 탭 | 줄 | 칸 |
|---|---|---|
| **기본** | 모양 | 재질 · 표시 이름 · 설명 · 겉모습 |
| | 분류 | 종류 · 소분류 · 등급 |
| **능력** | 무엇을 하나 | 능력치 · 기능 · 공격 방식 · 강화·진화 · 채굴 등급(도구) |
| | 무엇이 붙나 | 인챈트 · 커스텀 인첸트 · 수식어 · 세트 |

## 능력치

다섯 갈래로 나뉘고, 능력치 화면 아래 버튼으로 갈래를 고릅니다. 관리자 입장에서는 전부 "이 칼의
능력치"일 뿐이라 바닐라 속성인지 우리가 계산하는지는 화면에서 구분하지 않습니다.

| 갈래 | 예 |
|---|---|
| 공격 | 공격력·공격 속도·치명타 확률/배수/피해 %·흡혈·추가 피해·몹/플레이어/발사체/언데드 추가 피해·기능 피해 |
| 방어 | 방어력·방어 점수·최대 체력·밀림 저항·피해 감소·회피·막기·가시·초당 체력 회복·몹/플레이어/발사체/낙하/화염 피해 감소 |
| 원소 | 화염·냉기·번개·독 피해와 저항 |
| 이동 | 이동 속도·점프력·안전 낙하 거리·오를 수 있는 높이·중력·크기·물속 이동 효율… |
| 기타 | 행운·블록 파괴 속도·채굴 효율·블록 닿는 거리·경험치 획득·재사용 대기 감소 |

**피해 계산 순서** — 추가 피해·원소를 먼저 더하고, 비율(몹·플레이어·발사체·언데드)을 곱하고,
치명타 배수를 마지막에 곱합니다. 반대면 추가 피해가 치명타를 안 타서 "치명타 2배"가 말과 다른
값이 됩니다.

**피해 감소 합산 상한은 80%** 입니다. 무적을 막기 위해서입니다 — 네 부위에 30%씩 붙이는 것은
흔한 실수인데, 그 결과가 죽지 않는 플레이어면 안 됩니다. **방어 점수**(MMOItems 의 defense)는 그와 따로
받는 피해에 100/(100+점수)를 곱합니다 — 100 이면 절반. 치명타 피해 %는 배수에 더합니다(2배 + 50% = 2.5배).

숫자는 **입고 든 것 전부의 합**입니다. 흉갑의 치명타도 칼의 치명타에 더해집니다.

### 굴림과 수식어

능력치마다 **폭**을 줄 수 있습니다. 폭 0.1 이면 아이템마다 대략 ±10% 로 흔들리고(정규분포),
최대 폭을 넘지 않습니다. 같은 칼 둘이 다른 숫자를 갖게 됩니다.

**수식어**는 만들 때 자기 확률로 붙어 이름 앞(또는 뒤)에 붙고 능력치를 더합니다. 예: 30% 확률의
"날카로운" (+3 공격력).

아이템에는 **숫자가 아니라 숫자를 만드는 재료**(굴린 편차·붙은 수식어 id)만 적힙니다. 그래서
정의의 기준값을 고치면 이미 나간 아이템도 굴린 편차를 지킨 채 새 기준을 따라갑니다.

## 세트

`관리 → 세트` 에서 세트를 만들고 벌 수마다 효과(능력치·물약·**인첸트 효과**)를 적습니다. 아이템 허브의 **세트**
칸에서 소속을 고릅니다. 2벌 효과와 4벌 효과는 **쌓입니다**. 로어에 세트 목록과 벌 수별 효과가
나옵니다.

- **인첸트 효과**(몇 벌 효과 화면의 49번): 인첸트 플러그인(inmc-enchants)의 효과 줄 — 피해 증가·물약·불태우기·번개 … 을
  공격·방어·채굴·낚기·"입고 있는 동안" 같은 발동 조건마다 적습니다. 화면은 인첸트 플러그인이 그리고 돌리는 것도 인첸트 엔진입니다
  (없으면 안 돕니다). 붙을 때·떨어질 때 알림도 여기서.
- 인첸트의 옛 방어구 세트·세트 무기는 처음 한 번 이리로 옮겨 옵니다(세트 효과 → 4벌, 그 세트의 무기 → 5벌).
- `/커스텀아이템 세트지급 <플레이어> <세트>` — 세트의 아이템을 전부 줍니다(보상 명령어용).

## 보석과 소켓

- 아이템의 **소켓** 화면에서 칸을 더합니다. 색(`any` 는 아무 보석이나)을 정할 수 있습니다

## 소모품과 도구

소모품 화면에서 켭니다.

| | |
|---|---|
| 체력 · 배고픔 · 포만감 | 우클릭으로 쓰면 채웁니다(먹기·마시기·놓기 대신) |
| 쓸 수 있는 횟수 | 0 이면 닳지 않습니다. 2 이상이면 겹치지 않습니다 |
| 재사용 대기 | 초 |
| 보석 빼기 · 감정서 · 분해 도구 · 수리량/수리 비율 | **끌어다 놓아 쓰는 도구**가 됩니다. 이런 힘이 있으면 우클릭으로는 안 쓰입니다 |

물약·명령어·소리 같은 효과는 **기능** 화면에서 발동 조건 `사용` 으로 붙입니다.

**바닐라 설치·소모 막기**(아이템 설정 36번, 파일로는 `prevent-vanilla-use: true`) — 돌·흙으로 만든 재료가 우클릭에 놓이거나,
빵·물약으로 만든 증표가 먹히지 않게 합니다. 소모품이 아니어도 됩니다.

- 먹기·마시기: 아이템에서 **먹는 부품(`consumable`)을 뗍니다** — 먹는 모습조차 안 나옵니다. 끄면 재질 기본값으로 돌아옵니다.
  설정을 켜기 전에 나간 아이템은 다시 그려질 때(자동 갱신) 떼어지고, 그 전에는 먹는 끝에서 막힙니다
- 놓기: 그 블록으로 놓는 것(`BlockPlaceEvent`)을 막습니다
- 우클릭 **기능** · **소모품** · **커스텀 블록**(블록 설정)은 그대로 동작합니다

## 공격 방식

무기 종류마다 다른 공격(MMOItems 의 무기 종류). 허브의 **공격 방식** 칸에서 고릅니다.

| | |
|---|---|
| 단검 | 등 뒤에서 치면 피해 ×1.5 |
| 창 | 맞힌 적 뒤로 3칸 안의 적도 꿰뚫어 피해 50% |
| 망치 | 맞힌 자리 둘레 2.5칸의 적에게 피해 40% + 띄움 |
| 건틀릿 | 맞힌 적을 멀리 밀쳐냄 |
| 채찍 | 허공에 좌클릭하면 8칸 앞의 적을 칩니다 |
| 지팡이 | 좌클릭으로 20칸 마법탄 |
| 머스킷 | 우클릭으로 40칸 즉발 사격, 피해 ×1.5 (1.5초에 한 발) |

원거리 방식의 피해는 **공격력 속성**에서, 한 발의 간격은 **공격 속도**에서 옵니다. 맞히면 평소 근접
공격처럼 능력치(치명타·흡혈…)와 적중 기능을 탑니다. 창·망치의 튄 피해는 **몹에게만** 갑니다.

## 강화와 진화

0강(기본)에서 n강까지. 최대 강화한 뒤에는 다음 아이템으로 **진화**합니다.

### 강화 방식 — 공용과 아이템 전용

- **공용 강화 방식**(`관리 → 강화 방식`, `upgrades.yml`) — 무기용·방어구용처럼 여러 아이템이 함께 씁니다.
- **아이템 전용 표**(아이템 설정 → `강화·진화` → 강화 방식 → `이 아이템 전용 표`) — 그 아이템만 따로.
  공용 방식을 쓰던 아이템에서 만들면 그 표를 베껴 시작합니다.

단계 능력치를 적는 방식이 둘입니다.

| | |
|---|---|
| 증가량 | 단계마다 **더하는** 고정값(공격력 +2)과 기본 능력치의 %(+5%). 누적됩니다. 공용 방식에 맞습니다 |
| 단계별 전체값 | "+7 일 때 능력치 **전체**"를 그대로 적습니다(MMOItems 에서 단계마다 아이템을 따로 만들던 방식). 능력치를 안 적은 단계는 앞 단계를 잇습니다 |

단계마다 정하는 것: **성공 확률 · 실패하면(그대로 / 한 단계 하락 / 0강 초기화 / 파괴)** · 능력치 · 이 단계부터 **등급** ·
이 단계부터 **모양**(텍스처 · 모델). 이름 뒤에 `+N` 이 붙고, 로어에 지금 단계와 다음 단계의
성공 확률·실패 결과가 보입니다. 파괴돼도 박혀 있던 보석은 돌려줍니다. 가운데 단계는 지우지 않습니다 — 뒤 단계가
당겨져 이미 강화된 아이템의 능력치가 바뀌기 때문에 **끝에서만** 지웁니다.

### 강화석

소모품 화면에서 `강화석` 을 켭니다. 강화할 아이템 위에 **끌어다 놓으면** 한 단계 강화를 시도합니다.

| 강화석 쪽 규칙 | |
|---|---|
| 쓸 수 있는 강화 방식 | 무기 강화석·방어구 강화석처럼. 비우면 전부 |
| 쓸 수 있는 아이템 | 특정 아이템 전용 강화석. 여기 고른 아이템은 방식 제한과 상관없이 됩니다 |
| 단계 구간 | 예: 상급 강화석은 +6 ~ +10 에서만. 최대 `-1` 은 끝까지, `0` 은 0강에서만(1강 강화권) |
| 성공 확률 | 0 이면 단계의 확률. 정하면 단계 확률 **대신** 이 확률(MMOItems 식). **대상 등급별 확률**을 정하면 그게 먼저 |
| 성공 확률 보너스 | 위에서 정해진 확률에 더합니다(%p) |

아이템 쪽에서도 **"이 강화석으로만"** 을 고를 수 있습니다(`강화·진화` → 쓸 수 있는 강화석).

### 진화

`강화·진화` 에서 진화할 아이템을 고릅니다. 강화표가 있으면 **최대 강화에서만**, 없으면 언제든 진화합니다.

| | |
|---|---|
| 넘길 것 | 새로 0강 · 보석 반환 / 보석·굴린 능력치·수식어 계승(대상에 맞는 것만, 못 박는 보석은 반환) / 아무것도 안 넘김 |
| 진화석으로 | 진화석(소모품 화면)을 아이템 위에 끌어다 놓습니다. 진화석마다 쓸 수 있는 아이템을 정할 수 있습니다 |
| 제작대에서 | 제작대(`/제작`) 아래의 **진화** 버튼 → 가방에서 지금 진화할 수 있는 것만 보입니다. 재료를 정할 수 있고, 특정 제작대로 묶을 수 있습니다 |

## 부적·유물·장신구와 장착 칸

| 종류 | 효과가 나는 곳 | 규칙 |
|---|---|---|
| 장신구 | 손 · 장착 칸 | 여러 개가 다 붙습니다 |
| 부적 | **가방 어디든** · 장착 칸 | 여러 개가 다 붙습니다. 아이템 설정의 **같은 부적 중복 안 함**을 켜면 같은 부적은 가장 높은 강화 단계 하나만(강화 단계가 달라도 같은 부적) |
| 유물 | **가방 어디든** · 장착 칸 | 종류가 달라도 **한 번에 하나만** — 등급이 가장 높은 것, 같으면 강화 단계가 높은 것, 그것도 같으면 장착 칸·앞 칸의 것 |

한 칸에 겹쳐 든 묶음은 하나로 셉니다. 부적·유물의 바닐라 속성(최대 체력 등)은 아이템에 달지 않고 사람에게 직접 겁니다
— 손에 들었을 때 두 번 붙지 않게.

로어에는 종류 바로 밑에 **표찰**이 한 줄씩 붙습니다(이름표는 그라데이션):

| 표찰 | 붙는 것 |
|---|---|
| `소지 효과 — 가방에 지니기만 해도 발휘` | 부적·유물(가방에서도 효과가 날 때) |
| `장착 효과 — 장착 칸(/장비)에 끼워야 발휘` | 장착 칸에서만 효과가 나는 장신구·부적·유물 |
| `중복 불가 — 같은 부적은 가장 높은 강화 하나만` | 같은 부적 중복 안 함을 켠 부적 |
| `단 하나 — 여러 유물 중 가장 높은 등급 하나만` | 유물 |

기능도 같습니다 — 부적·유물과 장착 칸의 것은 **지속** 기능이 그 자리에서 돌고, **적중·처치** 기능은 어느 무기로 쳐도
돕니다(MMOItems 의 장신구처럼). 들거나 입는 평범한 아이템은 지금처럼 들거나 입어야 돕니다.

**장착 칸에서만 효과** — `관리 → 장착 칸 설정` 의 **가방·손에서도 효과**를 끄면 장신구·부적·유물은 `/장비` 칸에 끼워야만
능력치·기능이 납니다. 가방·손에 든 것은 전부 멈춥니다(능력치·지속·적중·처치·손에 든 클릭까지). 로어의 표찰도
"장착 효과 — 장착 칸(/장비)에 끼워야 발휘" 로 바뀌고, 켜고 끄는 순간 접속한 사람의 가방·장착 칸이 다시 그려집니다.
아이템마다 아이템 설정의 **효과가 나는 곳**(35번)으로 따로 정합니다 — 서버 설정 따름 → 장착 칸에서만 → 가방에서도.
파일로는 `equipment.yml` 의 `inventory-effects`(기본 `true`), 아이템의 `inventory-effect`(안 적으면 서버 설정).

### 장착 칸 — `/장비`

가방이 모자라지 않게 장신구·부적·유물을 끼워 두는 곳입니다(별칭 `/장신구` `/equipment` `/acc`, 권한 `incustomitems.equipment`).
유저메뉴에서는 이 명령을 부르면 됩니다.

- 줄마다 한 종류, 칸마다 한 개. 끌어다 놓거나 가방에서 Shift+클릭으로 넣고, 클릭하면 꺼냅니다(Shift+클릭은 가방으로).
- 기본 칸 수는 `관리 → 장착 칸`(장신구 4 · 부적 4 · 유물 1). 권한 `incustomitems.slots.<accessory|talisman|relic>.<1~8>` 로
  더 엽니다(기본값보다 클 때만). 권한을 잃으면 그 칸은 잠기고 효과가 없지만 꺼내기는 됩니다.
- **죽으면 가방과 같이 처리됩니다.** 인벤키퍼가 있으면 같은 드랍 비율·무덤·영혼각인 규칙을 타고, 없으면 바닐라처럼
  떨어집니다. 게임룰 `keepInventory` 면 그대로 남습니다.
- 칸을 바꿀 때마다 `plugins/inmc-customitems/equipment/<uuid>.yml` 에 즉시 저장합니다(서버가 꺼져도 복사·증발 없음).

### 배낭 — 장신구·부적·유물 한 개마다의 창고

아이템 설정 **용도** 탭의 **배낭**(장신구·부적·유물에만 보임)에 크기를 적으면 그 아이템이 배낭이 됩니다. 파일로는 `backpack: <칸 수>`.
누를 때마다 한 줄(9칸)씩 바뀌고, 칸 제목에 **몇 줄 화면이 되는지**(45칸이 넘으면 몇 페이지인지) 바로 나옵니다.

| | |
|---|---|
| 여는 법 | **들고 우클릭**(웅크려 우클릭 기능이 있으면 그쪽, 상자·문을 누르면 그 블록) · 장착 칸에 끼웠으면 **`/배낭`**(별칭 `/backpack`, 권한 `incustomitems.backpack` 기본 모두) · **빠른 동작 키(기본 G)** 의 [배낭 열기] · `/장비` 화면에서 끼운 배낭을 **우클릭** |
| 크기 | 자유 — 좌/우클릭 ±9칸 · Shift ±90칸 · 숫자키로 직접. 45칸이 넘으면 페이지(맨 아래 줄 ◀ ▶). 최대 900칸 |
| 내용물 | **아이템에 붙습니다**(셜커 상자처럼) — 한 개마다 창고가 따로고, 주거나 떨어뜨리면 같이 갑니다 |
| 끼운 것이 여럿 | `/배낭` · G 가 고르기 화면을 띄웁니다 |

- 내용물은 아이템이 아니라 `plugins/inmc-customitems/backpacks/<배낭 번호>.yml` 에 있고, 아이템에는 번호(`inmc:backpack`)만
  찍힙니다(처음 열 때). 크기가 자유라 아이템에 넣으면 그 아이템이 오갈 때마다 클라이언트로 가는 데이터가 부풀기 때문입니다.
  그래서 **아이템이 복사돼도 내용물은 늘지 않습니다**(같은 창고를 가리킬 뿐).
- **한 번에 한 사람만** 엽니다(두 화면에서 같은 물건을 꺼내 복사되지 않게). 배낭은 겹치지 않습니다(한 개씩).
- **배낭 안에 배낭은 못 넣습니다**(셜커 상자처럼) — 클릭·Shift·숫자키·F·끌기 전부.
- 바꿀 때마다 곧바로 파일에 쓰고, 닫을 때 플레이어 데이터도 같이 저장합니다.
- **분해하거나 강화 실패로 부서지면 안의 물건을 돌려받습니다**(박힌 보석과 같이). 진화하면 새 아이템이 같은 창고를 이어받습니다.
- 크기를 줄여도 물건은 사라지지 않습니다 — 들어 있는 가장 뒤 칸까지는 보이고, 비우면 줄어듭니다.
- ⚠ 배낭 아이템이 용암·공허·사라짐으로 **없어지면** 창고 파일은 남지만 꺼낼 길이 없습니다.

### 빠른 동작 키(G) — 모드 없는 단축키

1.21.6 부터 순정 컨트롤에 **빠른 동작(Quick Actions, 기본 G)** 키가 있습니다 — 서버가 정한 창을 여는 키입니다. 서버가 켜질 때
"빠른 메뉴" 창을 등록해 이 키에 겁니다(`CustomItemsBootstrap` — 레지스트리는 서버가 켜지기 전에만 고칠 수 있어 재시작해야
적용). 창의 **[배낭 열기]** 가 `/배낭` 과 같습니다. 키는 플레이어가 조작 설정에서 아무 키로나 바꿀 수 있습니다.
순정 클라이언트에서 서버가 **새 키 자체를** 만들 수는 없어서(모드가 필요) 키 → 창 → 버튼 한 번입니다. 다른 기능(플레이어 메뉴 등)도
이 창에 버튼을 더해 모을 수 있습니다.

## 기능

**발동 조건 + 효과 + 확률 + 쿨다운** 입니다. 같은 효과를 여러 조건에 붙일 수 있습니다.

**발동 조건 (15)** — 우클릭 · 좌클릭 · 웅크려 우클릭 · 웅크려 좌클릭 · 적중 · 처치 · 피격 · 지속(주기마다) ·
사용(소모품) · 웅크리기 · 점프 · 쏘기 · 발사체 적중 · 블록 캐기 · 죽음

웅크려 클릭은 그 기능이 있을 때만 갈라집니다 — 없으면 평소 클릭으로 돕니다. 웅크리기·점프·피격·지속·죽음은
**입고 든 것 전부**에서 돕니다.

**효과 (25)**

| | |
|---|---|
| 기본 | 물약 효과 · 피해 · 회복 · 점화 · 번개 · 돌진 · 순간이동(벽을 통과하지 않습니다) · 소리 · 입자 · **명령어** · 메시지 |
| 스킬 | 화염구 · 화살 세례 · 충격파 · 범위 피해 · 범위 물약 · 끌어당기기 · 밀쳐내기 · 얼리기 · 폭발(블록 안 부숨) · 광선 · 운석 · 연쇄 번개 · 범위 회복 · 흡수 |

피해를 주는 스킬은 **기능 피해** 능력치를 탑니다. 범위 효과는 기본으로 몹에게만 가고, 플레이어까지
치려면 "플레이어도" 를 1 로. 기능이 준 피해는 무기 공격이 아니라서 치명타·적중 기능을 다시 타지
않습니다(안 그러면 기능이 자기를 부릅니다).

**명령어 효과가 탈출구입니다.** 여기 없는 것은 명령어로 하면 됩니다.

확률과 쿨다운은 **모든 기능이 공통으로** 갖습니다. 재사용 대기 감소 능력치는 최대 80% 까지 먹습니다.

로어에는 기능마다 `▸ 발동 조건: 효과` 한 줄이 붙습니다. **물약 효과 · 범위 물약은 어떤 효과인지** 적습니다 —
`지속 효과: 야간 투시` · `우클릭: 신속 II 5초` · `적중: 대상에게 구속 3초` · `적중: 주변에 독 5초`(지속은 계속 다시 걸려 시간을
안 적습니다). 효과 이름은 번역 열쇠라 **보는 사람의 말**로 나옵니다.

## 제작

### 제작대 (MMOItems 의 crafting station)

`관리 → 제작대` 에서 만듭니다. 조합법마다 결과·재료(칸에 끌어다 넣기)·요구 레벨·권한·걸리는 시간.

- 시간이 0 이면 바로 받고, 아니면 **대기열**(9칸)에 들어가 그만큼 뒤에 받습니다. 접속을 끊어도 흐릅니다
- 블록을 연결하면 그 블록을 우클릭해 엽니다. `/제작 <제작대>` 로도 엽니다
- 재료·결과는 우리 아이템·바닐라·MMOItems·손으로 만든 아이템 모두 됩니다

### 바닐라 조합법

`관리 → 제작대 → 바닐라 조합법` — 작업대(모양/무모양)·대장장이 작업대·화로·용광로·훈연기·모닥불·석재 절단기.
결과가 우리 아이템이어도 됩니다. 재료에 우리 아이템을 쓰면 **그 아이템이어야만** 맞습니다(같은 재질의
바닐라 아이템으로 대신할 수 없습니다).

## 커스텀 블록

ItemsAdder 가 하는 일. 아이템 설정 화면의 **블록** 칸에서 방식을 고르면, 그 아이템을 들고 우클릭해 블록으로 놓습니다.
랜덤박스의 **상자 모양**으로도 고를 수 있습니다. 관리 화면 오른쪽 위 **커스텀 블록** 버튼이 블록 아이템 전부·남은 칸·Paper 설정 상태를
모아 보여 주고, 누르면 그 블록 설정으로 갑니다.

야생의 진짜 블록처럼 **시간 들여 캡니다** — 단단함·맞는 도구·도구 등급을 블록마다 정하고, 부쉈을 때 나오는 것을 드랍 표로 정합니다.

| 방식 | 무엇 | 빈 자리 | 이럴 때 |
|---|---|---|---|
| **꽉 찬 블록** (소리블록) | 소리블록의 안 쓰는 상태(악기 × 음)에 모델을 입힘 — IA 의 `REAL_NOTE` | 650 | 정육면체 블록. 진짜 블록이라 가볍다 |
| **투명·자유 모양** (후렴초) | 후렴초 줄기의 여섯 면 상태 — IA 의 `REAL_TRANSPARENT` | 62 | 상자처럼 비어 있거나 모양이 자유로운 블록 |
| **엔티티** (방벽 + 모델) | 방벽 블록 + 그 자리에 떠 있는 모델(ItemDisplay) | 제한 없음 | 칸이 모자라거나 서버 설정을 못 바꿀 때. 블록 하나에 엔티티 하나라 많이 깔면 무겁다 |

```yaml
# items.yml — GUI 가 적습니다
example_crate:
  block:
    kind: transparent          # solid · transparent · entity
    state: "down=false,east=false,north=false,south=false,up=false,west=true"
    drop: false                # 부수면 이 블록이 나옴 (기본 true)

mythril_ore:
  block:
    kind: solid
    state: "instrument=basedrum,note=0"
    drop: false
    hardness: 6.0              # 기본 1.5(돌)
    tool: pickaxe              # pickaxe · axe · shovel · hoe · sword · shears
    tool-tier: 5               # 0 나무·금 · 1 돌·구리 · 2 철 · 3 다이아몬드 · 4 네더라이트 · 5~ 커스텀 도구
    harvest: break             # any · drops(기본) · break
    drops:
      '0': { item: "inmc:mythril", mode: REFERENCE, material: "minecraft:paper", min: 1, max: 2, chance: 80.0 }
    silk-touch: true
    fortune: true
    exp-min: 3
    exp-max: 7
```

**상태는 방식을 고를 때 빈 칸을 골라 적고, 다시 고르지 않습니다.** 상태가 곧 월드에 놓인 블록의 정체라, 바꾸면 이미 놓인 블록이
다른 블록으로 보입니다. 우리 아이템과 `pack/sources/` 의 팩이 쓰던 상태는 피합니다. 방식을 바꾸면 이미 놓인 블록은 이 아이템으로
알아보지 못합니다.

### 모양

| 적은 것 | 놓였을 때 |
|---|---|
| 모델 | 그 모델. **블록 모델**이어야 합니다(옛 IA 상자처럼) |
| 텍스처만 | 여섯 면이 그 텍스처인 정육면체(`cube_all`) — 가방 속 모습도 같은 정육면체 |
| 둘 다 없음 | 그릴 것이 없어 칸이 비어 보입니다. 리소스팩 빌드 결과에 **모양 없는 블록**으로 나옵니다 |

엔티티 방식은 **그 아이템의 모양 그대로** 떠 있습니다. 블록 상태 방식은 모양을 바꿨으면 리소스팩을 다시 만드세요.

리소스팩의 `blockstates/note_block.json` · `chorus_plant.json` 은 **섞지 않고 통째로 새로 씁니다.** 소리블록의 바닐라 파일은 모든 상태를
한 칸(`""`)으로 덮어 특정 상태와 같이 둘 수 없고, 후렴초는 여러 조각을 겹쳐 그려 한 상태에 모델 하나를 줄 수 없기 때문입니다. 대신
잃는 것이 없게 — 커스텀이 아닌 상태는 바닐라와 똑같이 그리고, `sources/` 의 팩(옛 IA 팩)이 쓰던 커스텀 상태도 읽어 와 같이 적습니다.
바닐라 모습으로 남겨 두는 칸(소리블록 `harp` 전부 · 후렴초 전부 거짓/전부 참)은 커스텀에 내주지 않습니다.

### 캐기 — 단단함 · 맞는 도구 · 도구 등급

블록 설정 화면(아이템 설정 → **블록**, 또는 **커스텀 블록** 목록에서)에서 정합니다. 캐는 시간은 **바닐라 공식 그대로**라, 단단함 1.5 에
곡괭이를 고르면 바닐라 돌과, 50 에 다이아몬드 등급이면 흑요석과 같은 시간에 캐집니다. 화면의 **캐는 시간** 칸이 맨손과 도구 재질마다 몇 초인지
보여 줍니다.

| 칸 | 뜻 |
|---|---|
| **단단함** | 바닐라와 같은 단위 — 흙 0.5 · 돌 1.5 · 철광석 3 · 흑요석 50. 0 이면 한 번에 |
| **맞는 도구** | 곡괭이·도끼·삽·괭이·검·가위. 이 도구면 재질만큼 빨리 캡니다(나무 2 · 돌 4 · 구리 5 · 철 6 · 다이아 8 · 네더라이트 9 · 금 12). 없으면 무엇으로든 맨손 빠르기 |
| **도구 등급** | 맞는 도구의 최소 등급 — 0 나무·금 · 1 돌·구리 · 2 철 · 3 다이아몬드 · 4 네더라이트 · **5 부터는 커스텀 도구** |
| **맞는 도구가 아니면** | `아무 도구나`(맞는 도구는 빠를 뿐) · `맞는 도구여야 나옴`(바닐라 — 느리게 부서지고 아무것도 안 나옴) · `맞는 도구여야 부서짐`(아예 못 캠) |

효율 인챈트·`채굴 효율` 능력치·성급함·채굴 피로·`블록 파괴 속도` 능력치·물속·공중(÷5)도 바닐라처럼 들어갑니다. 캐는 동안 금이 가는 모습이
둘레 사람에게 보이고(엔티티 방식은 방벽이라 안 보입니다), 다 캐면 도구 내구도를 1 씁니다. 등급이 모자라면 액션바로 필요한 도구를 알려 줍니다.

**다이아몬드보다 높은 광물 등급** — 블록의 도구 등급을 5 이상으로 두고, 그 블록을 캘 커스텀 곡괭이의 아이템 설정에서 **채굴 등급**을 5 이상으로
올립니다(도구 재질의 아이템에만 보이는 칸, Q 로 재질 기본값). 등급만 오르고 빠르기는 재질 그대로라, 네더라이트 곡괭이 재질에 등급 6 을 주면
"네더라이트 빠르기로 6 등급 광석까지 캐는 곡괭이"가 됩니다. 미확인 아이템은 감정 전까지 재질 등급입니다.

크리에이티브는 바닐라처럼 한 번에 부수고 아무것도 안 나옵니다. 다른 플러그인이 대신 부수는 길(여러 칸 캐기 인첸트 등)도 도구 규칙을 지킵니다.

### 나오는 것 — 드랍 표

| 칸 | 뜻 |
|---|---|
| **부수면 이 블록이 나옴** | 블록 자신. 광석처럼 다른 것만 주려면 끕니다 |
| **드랍 표** | 손에 든 것을 더하고(우리 아이템·MMOItems·바닐라 그대로), 항목마다 **최소~최대 개수와 확률(%)**. 항목마다 따로 굴립니다 — 100% 는 늘 나옵니다 |
| **섬세한 손길이면 블록 그대로** | 섬세한 손길 도구로 캐면 드랍 표 대신 블록 자신, 경험치 없음(바닐라 광석) |
| **행운이 개수를 늘림** | 드랍 표 개수에 바닐라 광석 공식(행운 III 이면 최대 ×4) |
| **경험치** | 최소~최대. 맞는 도구로, 섬세한 손길이 아닐 때 |

맞는 도구가 아니면(`맞는 도구여야 나옴`) 블록 자신도 드랍 표도 경험치도 안 나옵니다. 폭발은 도구를 안 보고 블록 자신과 드랍 표를 폭발의 떨굼
확률대로 떨굽니다.

### Paper 설정 — 블록 상태 방식이면 필수

```yaml
# config/paper-global.yml
block-updates:
  disable-noteblock-updates: true
  disable-chorus-plant-updates: true
```

끄면 옆 블록이 바뀔 때 소리블록 악기·후렴초 면이 다시 계산돼 **다른 블록으로 보입니다.** 꺼져 있으면 켜질 때 콘솔에 경고하고 블록 화면에
빨갛게 나옵니다. 켜면 서버의 진짜 소리블록은 악기가 늘 `harp` 입니다(IA 서버와 같습니다). 엔티티 방식은 이 설정이 필요 없습니다.

### 놓기와 부수기

- 놓기 — 들고 우클릭. 상자·문처럼 여는 블록에는 웅크려야 놓입니다(바닐라와 같다). 놓은 뒤 땅 보호 플러그인에 묻고 막히면 되돌립니다
- 부수기 — 위의 캐기·드랍 표대로. 바닐라 것(소리블록·후렴초 열매)은 안 나옵니다. 엔티티 방식(방벽)도 같은 시간 들여 캡니다
- 막는 것 — 소리블록 조율(우클릭)·울리기(치기·레드스톤), 우리 후렴초 블록을 미는 피스톤(열매로 부서진다). 소리블록은 밀려도 상태째라 그대로 둡니다
- **저절로 자란 후렴초**(엔드·농장)는 우리 블록이 아닙니다 — 우리가 놓은 자리를 청크에 적어 가립니다(`inmc:blocks`). 안 가리면 후렴초 농장이
  우리 아이템을 찍어 냅니다

### 옛 ItemsAdder 블록 옮기기

**커스텀 블록** 화면의 **옛 ItemsAdder 블록 옮기기** — `plugins/ItemsAdder/contents/<묶음>/config(s)/*.yml` 의 `REAL_NOTE`·`REAL_TRANSPARENT`
블록을 아이템으로 옮깁니다.

- 상태는 `pack/sources/` 에 넣은 **IA 팩이 그 모델에 준 것 그대로** 받습니다 — 그래서 **월드에 이미 놓인 옛 블록이 새 아이템으로 이어집니다.**
  옮기기 전에 IA 가 만든 팩을 `sources/` 에 넣어 두세요. 팩에서 상태를 못 찾은 블록은 결과에 따로 나옵니다
- 옮기는 것: 방식 · 이름 · 설명 · 모델 · `drop_when_mined` · `hardness` · `break_tools_whitelist`. 재질은 종이입니다(옛 재질로 두면 바닐라 조합 재료로 쓰입니다)
- `break_tools_whitelist` 는 **한 갈래의 도구**만 적혀 있을 때 맞는 도구 + 가장 낮은 등급 + `맞는 도구여야 부서짐` 으로 옮깁니다
  (`[IRON_PICKAXE, DIAMOND_PICKAXE]` → 철 곡괭이 이상). 곡괭이와 도끼가 섞여 있으면 도구 제한 없이 옮깁니다
- **안 옮기는 것**: 소리·부술 때 명령어(`events`)·광석 생성(`worlds_populators`)·IA 의 드랍 표(`loots/` — 드랍 표는 블록 화면에서 다시 적으세요) ·
  다른 방식(`REAL`·`REAL_WIRE`·`TILE` …)
- 같은 이름이 있으면 건너뜁니다 — 여러 번 눌러도 됩니다. 옮긴 뒤 리소스팩을 다시 만드세요

## 연동 값 — 다른 플러그인과 잇기

**이 플러그인이 존재하는 진짜 이유입니다.**

아이템에 `열쇠 = 값` 을 적어두면 다른 플러그인이 그걸 읽습니다. 이 플러그인은 열쇠의 뜻을
모르고, 읽는 쪽은 이 플러그인이 있는지 모릅니다.

### 낚싯대 만들기

낚시 플러그인에 따로 등록할 필요 없이 **여기서 만들면 됩니다.**

```
fishing.rod              1      ← 이 표시가 있어야 낚싯대로 인식됩니다
fishing.reel-power       15
fishing.line-strength    30
fishing.reel-durability  15
fishing.big-fish-chance  2
fishing.double-chance    3
fishing.max-fatigue      500
fishing.fatigue-recovery 50
fishing.grade-bonus.s    2      ← 등급별 추첨 보너스
fishing.minigame-time    2      ← 미니게임 제한 시간 +초
fishing.bait-save        25     ← 미끼를 안 쓸 확률 %
fishing.size-bonus       10     ← 크기 +%
fishing.fatigue-save     15     ← 자동 낚시 피로도를 안 쓸 확률 %
fishing.auto-catch-reduce 1.5   ← 자동 낚시 대기 −초
```

같은 열쇠를 **커스텀 인첸트**(inmc-enchants)의 레벨 `data` 에 적으면, 그 인첸트가 붙은 낚싯대에
값이 더해집니다.

배포본의 `example_rod` 가 그대로 쓸 수 있는 예시입니다.

낚시는 **커스텀아이템을 먼저 보고, 없으면 자기 `rods.yml` 을 봅니다.** 옮겨가는 중인 서버에서
양쪽이 다 돌게 하기 위해서입니다.

## 정의를 고쳤을 때 — 자동 갱신

**이미 나간 아이템도 따라 바뀝니다.** 아이템이 사람 눈에 들어오는 순간 — 접속(가방 전체) · 손에 쥘 때 ·
주울 때 · 상자를 열 때 — 정의가 바뀌었으면 다시 그립니다. 서버의 모든 상자를 훑을 방법은 없지만,
눈에 안 들어온 아이템은 옛 모습이어도 아무도 모릅니다.

다시 그릴 때 **그 아이템의 몫은 지킵니다** — 굴린 능력치 편차, 붙은 수식어, 박힌 보석, 남은 사용 횟수,
미확인 여부, 내구도, 모루로 붙인 인챈트, 부여서로 붙인 커스텀 인첸트.

`/커스텀아이템 갱신` 은 손에 든 것 하나를 지금 바로 다시 그립니다.

⚠ 보석의 정의(능력치)를 고치면, 그 보석이 **박힌** 아이템은 로어가 다음 갱신 계기까지 옛 숫자로
보일 수 있습니다(능력치 계산은 곧바로 새 값입니다). 손에 들고 `/커스텀아이템 갱신` 하면 맞춰집니다.

## 리소스팩 — 만들고 합치기

ItemsAdder 가 하는 일. **텍스처를 넣으면 팩을 만들어 주고, 다른 팩들과 합쳐 준다.**

```
plugins/inmc-customitems/pack/
  sources/          ← 합칠 팩들. zip 이든 폴더든
    10-inmc.zip     ← 처음 설치할 때 넣어 주는 서버 기본 팩(필요 없으면 지우세요 — 되살아나지 않습니다)
    20-extra/
  textures/         ← 아이템에 붙일 png
    boss_sword.png
  models/           ← 직접 만든 모델 json (선택)
  items/            ← 직접 만든 아이템 정의 json (선택 — 번호에서 옮긴 조건 있는 모양도 여기)
  output/
    pack.zip        ← 결과
    pack.sha1
```

### 쓰는 법

1. `pack/textures/` 에 png 를 넣는다
2. 아이템 설정 화면의 **겉모습** 칸에 그 파일 이름을 적는다
3. `/커스텀아이템 리팩 빌드`
4. `output/pack.zip` 을 아무 데나 올리고 `config.yml` 의 `resource-pack.url` 에 주소를 적는다

만들어 주는 것:

```
assets/inmc/textures/item/boss_sword.png   ← 넣은 png
assets/inmc/models/item/boss_sword.json    ← 그 텍스처를 쓰는 모델
assets/inmc/items/boss_sword.json          ← item_model 이 가리키는 정의
```

**모델 번호(`custom_model_data`)는 쓰지 않습니다.** 1.21.4 부터 아이템에 모델 이름을 직접 붙일 수
있어서(`item_model`) 번호를 나눠 줄 필요가 없습니다 — 아이템 id 가 곧 모델 이름입니다.
번호 방식은 **팩 두 개를 합칠 때 번호가 겹치는 것이 가장 흔한 사고**였고, 그 사고 자체가
없어집니다. 옛 정의에 남은 번호는 팩을 만들 때 저절로 옮깁니다 — 아래 “낡은 모델 번호” 참조.

### 합치기 — 이 기능의 핵심

`sources/` 의 팩들을 **이름 순으로** 읽고 나중 것이 이깁니다. `10-` `20-` 처럼 번호를 붙이세요.

**다만 json 은 덮지 않고 섞습니다.** 덮으면 두 팩 중 하나가 **조용히 사라집니다** — 오류도
안 나고, 게임에 들어가서 텍스처가 없는 걸 보고서야 압니다.

| 파일 | 규칙 | 안 지키면 |
|---|---|---|
| `pack.mcmeta` | 형식 번호는 가장 높은 것 · **오버레이 목록은 이음**(나중 팩의 것이 뒤 = 이김) | 낮은 쪽에 맞추면 높은 팩이 통째로 안 읽힘 · 목록을 덮으면 한 팩의 버전별 폴더(셰이더·모델)가 zip 에 있어도 안 켜짐 |
| `lang` 의 json | 키 단위 합침 | 한쪽 팩의 번역이 전부 사라짐 |
| `sounds.json` | 키 단위 합침 | 같은 이유 |
| `atlases` 의 json | `sources` 배열 이음 | 목록이라 덮으면 텍스처가 안 붙음 |
| `overrides` 가 있는 모델 | 배열 잇고 번호 순 정렬 | **가장 흔한 충돌.** 두 팩이 같은 바닐라 아이템을 오버라이드하면 한쪽 아이템이 전부 사라짐 |
| 그 외 | 나중 것이 이김 | 통짜 정의라 섞을 수 없음 |

**폴더째 압축한 팩**(맨 위에 폴더 하나, 그 안에 `pack.mcmeta` — BetterHud 의 빌드 폴더가 그렇다)은 그 폴더를 벗겨 읽습니다.
그대로 두면 `resourcepack/assets/…` 가 되어 클라이언트가 그 팩을 통째로 무시합니다.

**코어 셰이더는 섞을 수 없습니다.** 두 팩이 같은 셰이더(`rendertype_text` 등)를 가지면 나중 팩 것만 살고, 그 팩의 짝(`.vsh`/`.fsh`)이
갈라지면 글자가 통째로 안 그려집니다. 셰이더로 그리는 팩(BetterHud 등)은 **뒤 번호**로 두세요.

우리가 만든 에셋은 **맨 앞**(우선순위 가장 낮음)입니다 — `sources/` 에 넣은 팩으로 덮어쓸 수
있어야 하기 때문입니다.

### 낚시 아이템의 기본 그림

낚시의 물고기 · 생선살 · 미끼 · 낚싯대는 **그림이 이미 들어 있습니다.** 켜면 `pack/textures/fishing/` 에 png 가 깔리고, 낚시가
옮겨 온 아이템 중 **겉모습이 비어 있는 것**에 텍스처와 등급(물고기 F~S → 일반~신화)이 저절로 붙습니다. `/커스텀아이템 리팩 빌드`
후 팩을 다시 올리면 보입니다. 그림을 바꾸려면 같은 이름의 png 를 넣으면 되고(덮어쓰지 않습니다), 한 아이템만 다르게 하려면 그 아이템의
겉모습 칸을 고치면 됩니다(겉모습이 있는 아이템은 다시 건드리지 않습니다). 목록은 플러그인 안의 `role-appearance.yml` 입니다.

**낚싯대**는 재질이 낚싯대이고 텍스처만 적으면 손에 든 막대 모양(`handheld_rod`)으로 그려지고, 옆에 `<이름>_cast.png` 가 있으면
던졌을 때 그 모양으로 바뀝니다.

### 명령어

| | |
|---|---|
| `/커스텀아이템 리팩` | 리소스팩 화면 |
| `/커스텀아이템 리팩 빌드` | 만들기. **콘솔에서도 됩니다** — 배포 스크립트가 부를 자리 |
| `/커스텀아이템 리팩 정보` | 마지막 결과와 sha1 |

빌드는 **워커 스레드**에서 돕니다. 팩 하나가 수천 개 파일일 수 있어 메인에서 압축하면
서버가 몇 초씩 멈춥니다.

### 배포

이 플러그인은 팩을 **만들기만** 합니다. 올리는 것은 관리자 몫입니다 — 서버 안에 HTTP 서버를
띄우는 것은 포트를 열고 방화벽을 손대고 대역폭을 쓰는 일이라, 아이템 플러그인이 조용히 해도
되는 일이 아닙니다.

```yaml
resource-pack:
  url: "https://example.com/pack.zip"
  auto-send: true
  required: false
```

sha1 은 빌드할 때 저장되고 보낼 때 같이 넘어갑니다 — 클라이언트가 **이미 받은 팩인지
판단하는 근거**라, 없으면 접속할 때마다 몇 MB 를 다시 받습니다.

### 빠진 텍스처

파일 이름 오타는 **오류를 내지 않습니다.** 그 아이템만 조용히 바닐라 모양으로 나오는데,
게임에서 그걸 찾으려면 아이템을 하나씩 꺼내 봐야 합니다. 그래서 빌드 결과와 리소스팩
화면이 **빠진 텍스처 목록**을 따로 보여줍니다.

### 모델 목록

`관리 → 리소스팩 → 모델 목록`. **만든 팩에 들어 있는 모델 전부**를 게임에서 실제 모양으로 봅니다(바닐라 `minecraft` 와 IA 내부
`_iainternal` 은 뺍니다). 최신 방식은 번호가 없으므로, 팩을 만들 때 모델마다 미리보기 정의(`inmc:preview/<이름공간>/<경로>`)를 붙여
두고 아이콘이 그것을 가리킵니다. 모델마다 **쓰는 아이템**이 보이고, 보기는 전부 · 안 쓰는 것 · 쓰는 것, 이름공간별로 거를 수 있습니다.
좌클릭하면 그 모델로 **새 아이템**을 만들고(이름을 묻고 설정 화면으로 — 재질은 손에 든 것, 빈손이면 종이), Shift+클릭하면 한 개 받습니다.
**이름으로 찾기**(돋보기)로 모델 이름의 일부를 적어 거릅니다(우클릭 = 검색 지우기).
목록은 **만든 팩**을 읽습니다 — 팩을 고쳤으면 다시 만든 뒤 여세요.

아이템 설정의 **겉모습** 칸을 좌클릭하면 같은 목록이 **고르기 모드**로 열립니다 — 모델을 누르면 그 아이템의 모델이 되고 설정 화면으로
돌아갑니다. 지금 모델은 반짝이고, 그 쪽이 먼저 열립니다. 텍스처 파일 이름을 적으려면 Shift+좌클릭(채팅 입력)입니다.

### 낡은 모델 번호 (`custom_model_data`) — 쓰지 않습니다

모델 번호는 **쓰지 않고, 적을 수도 없습니다**(사용자 결정 2026-09-28). 옛 정의(MMOItems·ItemsAdder 에서 옮겨 온 것)나 다른 플러그인에서
옮겨 온 아이템에 번호가 남아 있으면, **`/커스텀아이템 리팩 빌드` 한 번이 전부 최신 방식으로 옮깁니다:**

1. 번호가 **지금 팩에서 실제로 무엇으로 그려지는지** 찾습니다 — 게임과 같게, 번호 이하 중 가장 큰 갈래 · 지금 판에 맞는 오버레이 폴더 ·
   1.21.4 정의가 없으면 낡은 `overrides`
2. 그 모양을 우리 아이템 정의(`assets/inmc/items/<이름>.json`, `item_model`)로 적고 아이템의 **모델** 칸에 그 모델 이름을 적습니다.
   조건이 있는 모양(던진 낚싯대 · 당긴 활 …)은 정의 통째로 `pack/items/<이름>.json` 에 남깁니다
3. 번호를 0 으로 만듭니다. 바닐라 모양으로 그려지던 번호(옛 팩이 빈 번호를 바닐라로 채워 둔 것)는 번호만 뗍니다 — 지금과 똑같이 보입니다.
   강화 단계의 번호도 같습니다(공용 강화 방식은 쓰는 아이템 모두에게 같은 모양일 때만)
4. **`sources/` 의 팩이 바닐라 아이템에 걸어 둔 번호 갈래를 지웁니다.** 번호로 그리던 것이 우리에게 더는 없으니 그 갈래는 이름만 차지하고,
   평범한 바닐라 아이템이 남의 팩 정의로 그려지게 만듭니다 — 옛 IA 팩의 `player_head` 정의가 다른 플러그인 화면의 플레이어 머리를
   이상하게 그렸습니다. 번호 갈래만 있던 정의는 파일째 빼서 클라이언트가 제 판의 바닐라 정의를 쓰게 하고, 바닐라 아이템을 새로 그린
   팩이면 그 모양만 남깁니다. 낡은 `models/item/*.json` 은 번호 조건의 `overrides` 만 뺍니다

이미 나간 아이템은 정의가 바뀌었으니 다음 계기(쥘 때 · 주울 때 · 접속 · 상자 열 때)에 번호 없이 다시 그려집니다. **새 팩을 올려야**
보입니다. 리소스팩 화면의 **모델 번호** 칸이 남은 번호 수와 지난 빌드에서 옮기고 걷어 낸 수를 보여 줍니다.

⚠ **다른 플러그인이 번호로 그리던 아이템**(메뉴 플러그인의 아이콘 등)도 걷어 내기에 같이 영향을 받습니다 — 그런 것은 그 플러그인에서
`item_model` 로 바꾸세요.
